# Experimental NVIDIA Turing support

QEngine can target CUDA compute capability 7.5, including CUDA-enabled CMP 50HX cards. Build the same model engines with an explicit architecture.

```sh
cmake -S . -B build-sm75 -G Ninja -DCMAKE_CUDA_ARCHITECTURES=75 -DCMAKE_BUILD_TYPE=Release
cmake --build build-sm75 --target qengine qflash cuda_compat_unit
ctest --test-dir build-sm75 -R '^cuda_compat_unit$' --output-on-failure
```

For a text-only container build, use:

```sh
docker build -t qengine:cmp50 --build-arg CUDA_ARCHS=75 --build-arg VISION=0 .
```

Use a CUDA toolkit and driver that support Turing and check that CUDA can see the cards before loading weights. The changes in this branch cover the inference engine. The host's GPU driver, memory configuration and PCIe connectivity are prerequisites.

- The existing FP16 and INT8 kernels use smaller native Turing Tensor Core instructions with the same warp fragment layout. BF16 fragments use FP32 fused multiply-adds to keep the BF16 exponent range. Shared-memory copies run synchronously with CTA-scoped ordering.
- When larger tiles exceed the per-block shared-memory limit, the engines use smaller attention kernels or alternate layouts. Prefill uses the recurrent GDN path when the chunked kernel cannot fit. The Q8 checkpoint path uses FP16 GEMM when the W8A8 double buffer cannot fit. Optional LSA falls back to full attention.
- The GPU test checks fragment layouts against independent matrix products and exercises the shared-memory copy and barrier over multiple phases. It skips on machines without a CUDA device. Inference accuracy, available context, throughput and multi-GPU stability still need to be measured on CMP 50HX.
